I administer brand and community Discord servers in a local browser profile that holds that Discord login and nothing else. Personal Discord stays out. I will not write a token farm or a "free nitro accounts" chapter.

The useful caveat: Discord's desktop app is not MaskWright. This page is the web (or in-browser) session on Windows 10/11 when you choose to run Discord that way, plus the same cookie-store rule if you ever paste a session into Chromium. Authorized servers only.

## Why a separate profile

Discord tokens and cookies are the login. Two brand servers on two logins in one store is a mix waiting to happen. [Cookie jars are not optional](/blog/cookie-jars-are-not-optional). [Multiple accounts on one PC](/blog/multiple-accounts-on-one-pc).

MaskWright 0.1: per-profile `user-data-dir`. `profiles.json` is encrypted. Chromium user data is not. No seats. Bring your own HTTP or SOCKS5 if that community already uses an exit.

## Roles, not token dumps

Invite moderators with Discord roles. They sign in as themselves. I do not export cookies. I do not mail user tokens. Same rule as every other network on this desk.

Unofficial helpers that want the token: no. Same stance as [X API versus unofficial helpers](/blog/x-api-versus-unofficial-helpers).

| --- | --- |
| Brand/community login you admin | Personal Discord |
| Official bot dashboards you already use | Token stealers, unofficial "raid" tools |
| Optional community proxy | Gmail / X / Telegram work |

## Web versus the Discord app

The Discord native app has its own storage. A MaskWright profile does not replace it. If you use the native app for voice, keep the brand login there as Discord designed, and still do not mix brand and personal in one Discord app user if Discord lets you separate them. I do not document app-level exploits.

2FA stays on a device I hold.

## On a real Windows desk

If I use Discord in the browser, it is `acme-discord` and nothing else. I pin the official Discord web URL. I do not install unpacked "token login" helpers. I do not paste a token into DevTools.

The native Discord app is a separate store. I do not treat MaskWright as a replacement for voice. I do treat cookie isolation as mandatory if two Discord logins must not meet.

Mod logs and ban lists, if exported, go to the community's ops, not into Gmail's profile and not into X ads. OneDrive Desktop is how those exports leak.

Co-owners get Discord roles. They sign in as themselves. When they leave, I remove the role. I do not try to expire a file I already sent.

Household IP is normal. I do not buy a "Discord residential" as theater unless the community already had an exit requirement.

## FAQ

### Can one Discord login hold five brand servers?

Yes, Discord is built that way. One login can still deserve one folder so Gmail and X do not sit beside it. If two logins are two brands, two folders.

### Self-bots?

No. Against Discord's rules. MaskWright is not a Playwright product and is not a self-bot host.

### Restore a disabled Discord login?

Complete Discord's process as the owner. I will not write a bypass.

### Cloud Discord?

The vendor holds the token. I keep community admin on local disk when I use the browser. [Compare local versus cloud](/compare).

### Can I paste a Discord token into the profile to skip QR login?

No. A token is the login. Sign in as yourself. Invite others with roles.

Admin the servers you were given. Put that login in a local folder. Invite mods with roles. Leave farms and token dumps out.

I skip self-bots, token stealers, and cloud Discord so a vendor holds the community. I keep exports of mod logs in ops, not on a synced Desktop. Household IP is normal. I close the browser session when queue work is done.
